**Behaviour change:** every Gemini finish reason is mapped on purpose. On the native wire (`createGoogleNative`) and in batch results, the filters `SPII`, `IMAGE_PROHIBITED_CONTENT` and `IMAGE_RECITATION` now end a turn with `'content_filter'`, like `SAFETY`, `RECITATION`, `BLOCKLIST`, `PROHIBITED_CONTENT` and `IMAGE_SAFETY`; they ended it with `'stop'`. `CONTINUATION` ends it with `'length'` instead of `'stop'`, since Deuz sends no continuation token. The stops that leave no usable answer (`LANGUAGE`, `OTHER`, `MALFORMED_FUNCTION_CALL`, `UNEXPECTED_TOOL_CALL`, `TOO_MANY_TOOL_CALLS`, `NO_IMAGE`, `IMAGE_OTHER`) end it with `'error'` instead of `'stop'`, so a native run stops with reason `'error'` instead of completing with an empty answer. `STOP`, `FINISH_REASON_UNSPECIFIED` and any value `@google/genai` 2.28 does not list still end it with `'stop'`. Because Gemini finishes a turn that called a function with `STOP`, a turn that carried a call ends with `'tool_calls'`; that rule no longer hides a filter or a limit. A turn that streamed a call and was then filtered or cut off ends with `'content_filter'` or `'length'` instead of `'tool_calls'`, so the finish-reason gate holds the call back in both loops and in native runs.

**Behaviour change:** a streamed OpenAI Responses turn that its content filter cut off (`response.incomplete` with `incomplete_details.reason: 'content_filter'`) ends with `'content_filter'` instead of `'stop'`, or `'tool_calls'` when it streamed a call, so the finish-reason gate holds that call back. `max_messages` and `steered` still end a turn as a complete response does.

**Behaviour change:** an OpenAI refusal is kept. Both OpenAI wires dropped the model's refusal text (Chat Completions `delta.refusal`, Responses `response.refusal.delta` and `response.refusal.done`), so a refused answer looked like an empty one that ended with `'stop'`. A refused turn now ends with `'content_filter'`, as an Anthropic refusal does, unless the provider reported `'length'` or `'content_filter'` itself. The refusal text is its stop explanation, `stopDetails: { type: 'refusal', explanation }`, on `generateText`, `streamChat`, `generateObject`, `streamObject`, `NoObjectGeneratedError`, native runs (which stop with reason `'refusal'`), the UI wire and batch results, and the `finish` part keeps it as `providerMetadata.openai.refusal`, the key the batch parsers use. The refusal never becomes answer text, and a refused turn dispatches none of its tool calls. The batch parsers share each streaming adapter's finish mapping, so a batch result ends as the same reply does when streamed.

No public type changes: `FinishReason` and `StopDetails` keep their shapes. Wire shapes follow the types of `openai` 7.32.0 and `@google/genai` 2.28.0; not live-verified.
