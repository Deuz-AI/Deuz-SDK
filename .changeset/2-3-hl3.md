Headless preview: reports and `resumeHeadless` take the native durability options of 2.3. A pending action for a call whose effect is unknown names both answers, `resumeWith: ['retryToolCallIds', 'reconciledToolResults']`: check the effect, then run the call again or record the result that landed, so it never runs again. A failed run whose stored envelope records a transient cause (a model call that failed in transit: a network or provider error, a transport timeout, an open circuit breaker or a stream that broke off; or a budget admission refused with a serialization conflict) carries a new report field, `retry` (`cause`, `phase`, `resumeWith: 'retryFailed'`), on the leg's report and in `inspectRun`: resume it with `retryFailed: true` to go on from its last checkpoint. Its outcome and exit code stay as before: `failed` (exit 1), or `limit` (exit 6) for a transport timeout. A retried resume that stops again before its first write, on an unknown effect for example, keeps `retry`, so the next resume passes `retryFailed: true` with its answers. A resume refused before it wrote anything (a changed binding, answers the run cannot take, `retryFailed` for a failure that was not transient) reports its own error without `retry`, and the stored run stays as it was. New type `HeadlessRetry`.

`examples/13-headless`: `resume` takes `--retry-call <call-id>`, `--reconcile <file.json>` (the results that landed) and `--retry-failed`, and two keyless scenarios show them: `--mock crash` makes the run store go down while a tool runs, leaving an unknown effect, and `--mock outage` opens the circuit breaker so the model call fails in transit. Relative paths and the project instructions are taken from the directory the command was started in. A `--reconcile` file that cannot be read as JSON is a usage error (exit 2); the other exit codes are unchanged.

The headless docs and JSDoc now also say that `runHeadless` rejects an invalid `projectInstructions` option, that a skill folder that does not exist adds no skills, and what the report's `verification` field holds.
