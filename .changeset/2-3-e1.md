'@deuz-sdk/core': minor

`createNodeSandbox` (`@deuz-sdk/core/compute/node`) no longer takes the host process down when a child stops reading its stdin. A child that exited, crashed or closed stdin before reading an input larger than 64 KiB raised an uncaught `write EOF` (Windows) or `EPIPE` (Linux) that killed the caller, and its `try`/`catch` never ran. stdin is now written with backpressure, and a child that stops reading ends the write quietly; the run settles once with the child's exit code and output and releases its timer and abort listener. Without `stdin` the child now gets the null device instead of a pipe that was never closed, so a program that reads to EOF (`sort`, `cat`, `node` reading a script) finishes at once instead of waiting out the timeout; `stdin: ''` is still an empty pipe. `runShell` takes `stdin` the same way `runCode` does. A timeout or abort settles within half a second of the kill even when a program the shell started (any command under `cmd.exe /c`, or `a` in `bash -c 'a && b'`) still holds the output pipes; that program is not killed. `createFileWorkspace` (`@deuz-sdk/core/workspace/node`) accepts names that merely start with two dots, such as `..notes`, `...` and `..notes/x.txt`, which its own containment checks used to refuse as traversal; a real `..` segment is still refused. Behaviour change: its `exists()` and `delete()` now reject an illegal or escaping path the way `read()` and `write()` do, and the way `createInMemoryWorkspace` always has, instead of answering `false` or reporting success while doing nothing. `delete()` rejects when it cannot remove what is there (a directory, for example) and `exists()` surfaces filesystem errors other than a missing path; a missing path is still `false` for `exists()` and a no-op for `delete()`. `list(prefix)` rejects an illegal prefix even when the workspace is empty.
