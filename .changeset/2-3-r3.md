Native runs can be listed on Redis. The `agentRuns` of `createRedisOpsStore` (`@deuz-sdk/core/ops/redis`) now implements `AgentRunStore.list` with the contract the memory, SQLite and Postgres stores share: newest save first, then run ID descending, an opaque `cursor` while more runs follow, the `phases`, `scope` and `updatedBefore` filters, and the stored result's `status`. So `findStaleAgentRuns` from `@deuz-sdk/core/ops` works on Redis as well. A run's `updatedAt` is the server's `TIME` at its last save. The Lua script that checks and writes the run's revision also keeps sorted-set indexes of the runs under the store's hash tag: every run, by phase, by scope, and by both. The prune script removes pruned runs from them. A listing reads only the index it needs and loads no run, and runs saved in the same millisecond are ordered by run ID exactly as JavaScript compares strings. The key layout version stays 1. Widened public type: `RedisOpsStore['agentRuns']` declares `list`.
