Redis backends for operations, budgets and swarms, promised for 2.3 in the 2.2 notes. `@deuz-sdk/core/ops/redis` adds `createRedisOpsStore({ client | url, prefix? })`, which returns `leases`, `agentRuns`, `claims` and `close()` with the 2.3 semantics of the SQLite and Postgres ops stores (acknowledged cancels, a revision compare-and-set on every agent run save, retention on all three), and `createRedisBudgetStore`, a `BudgetStore` with `holds`, `sweep` and `prune` that admits, settles and refuses exactly like the others. `@deuz-sdk/core/swarm/redis` adds `createRedisSwarmStore`, a `SwarmStore` with the `'spawn'`, `'channels'` and `'list'` capabilities, `head` and `prune`. Every operation is one Lua script, so it is atomic on the server, with no `WATCH`/`MULTI`; lease, claim and budget-window time is the server's `TIME`, never a host clock; and every key of a store carries one hash tag (`{<prefix>:ops}`, `{<prefix>:budget}`, `{<prefix>:swarm}`), so a Redis Cluster keeps each store in one slot. A swarm commit validates at the run's revision and writes only while the run is still at that revision and generation, so a concurrent writer gets `SwarmConflictError` and a run pruned and created again under its key never takes a write meant for the old one. Retention removes at most 1 000 entries per script and loops, so a large backlog never holds the server in one long script. Each store stamps its key layout version (`<tag>:schema`, 1) on first use and refuses another, as the SQL stores refuse a newer schema. The stores need Redis 7 or later. Their conformance suites run offline on ioredis-mock, which executes the same scripts, and on a real Redis when `DEUZ_TEST_REDIS_URL` names one, as in the repository's CI.

The Redis store pack serves `runs`. `createRedisStores` now returns the `RunStore` the SQLite and Postgres packs already had, which the 2.0 notes listed for Redis before it existed: a record string plus one sorted set per status, written in the pack's crash-tolerant order, so `list({ status })` is an index read. It needs only the pack's existing commands. **`RedisStores` is widened with `runs`.**

The client seam runs scripts and takes ioredis. `RedisClientLike` gains an optional `eval(script, { keys, arguments })`, node-redis's `EVAL` signature; the new stores need nothing else (`RedisScriptClient`), so a connected node-redis client, standalone or cluster, fits as it is. `wrapIoredisClient(client)` fits an ioredis client to the whole seam, `eval` included, and answers an empty batch locally; `IoredisClientLike` is the structural shape it accepts. node-redis 6 fits the seam as v4 and v5 do, and the message for a missing optional `redis` peer now names v4, v5 or v6.

New exports: from `@deuz-sdk/core/ops/redis`, `createRedisOpsStore`, `createRedisBudgetStore`, `wrapIoredisClient` and the types `RedisOpsStore`, `RedisOpsStoreOptions`, `RedisBudgetStore`, `RedisBudgetStoreOptions`, `RedisScriptClient` and `IoredisClientLike`; from `@deuz-sdk/core/swarm/redis`, `createRedisSwarmStore`, `wrapIoredisClient` and the types `RedisSwarmStore`, `RedisSwarmStoreOptions`, `RedisScriptClient` and `IoredisClientLike`; from `@deuz-sdk/core/stores/redis`, `wrapIoredisClient` and the types `RedisScriptClient` and `IoredisClientLike`.
