`createContextCompiler` (preview) keeps placed context through compaction. When a compaction removes an earlier `<deuz_context>` block, the compiler places its entries again in the next package, and an overflow retry does the same for blocks its own compaction removed. If mandatory content, such as a loaded skill body, no longer fits on the retry, the retry throws `ContextBudgetExceededError` instead of leaving that content out. Only a record's latest placement comes back, so an older revision is never appended after a newer one. Each placed entry in the compiler state records its block's step (`ContextPlacedEntry.step`), and the compiler counts an entry as placed only while that exact block is still in the messages. A block that places entries again keeps the current pass number, so the pass alone cannot identify it. A compiler restored from a checkpoint does not have the candidates the earlier process retrieved. If a compaction removes a mandatory entry's block (`ContextPlacedEntry.mandatory`), the restored compiler asks that entry's source for it again, even past `refresh.maxPasses` and without spending a pass. Optional entries still wait for the next refresh.
