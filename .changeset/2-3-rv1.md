Realtime voice. `createRealtimeSession` in the new edge-safe `@deuz-sdk/core/realtime` opens a live speech-to-speech session with OpenAI Realtime (`createOpenAIRealtime`) or Gemini Live (`createGeminiLive`) over WebSocket, behind one event model: session lifecycle, input audio append and commit, output audio deltas, input and output transcripts, text, tool calls, interruption, turn end, errors and usage. `deps.webSocket` is the socket seam: the default is the runtime's global `WebSocket`, which sends a server-side API key as a handshake header in Node.js 22+ (or pass a `ws` socket), while a browser connects with an ephemeral token minted on your server by `createOpenAIClientSecret` or `createGeminiAuthToken`. Gemini tokens lock the session configuration by default. Tools are ordinary Deuz tools: they are validated, approval-gated (`approveToolCall`), timed out on `deps.clock`, and their errors go back to the model; a tool without `execute` waits for `session.sendToolResult`. OpenAI tool calls run only from a completed response, and a Gemini cancellation aborts the call. Usage is split by modality (text, audio, image) and priced per modality through `deps.priceProvider`; `realtimePriceTable` builds the rows, and a model without a price warns once (`unpriced-model`) while the session continues. No realtime prices ship. OpenAI's `interrupt({ playedMs })` cancels the running answer and truncates the audio to what the user heard. `sendRaw`, `rawEvents` and `providerOptions` cover anything the normalized API does not map. Sessions are single-use, `RealtimeError` carries a `kind` for every failure, and messages never contain the key or token. Not live-verified: both wires were derived from the official SDK types (`openai` 7.32, `@google/genai` 2.28) and are tested offline against a scripted socket and a local WebSocket server. WebRTC, Vertex AI Live and OpenAI transcription-only sessions are not covered; WebRTC is planned for 2.4.
