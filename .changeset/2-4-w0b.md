When SQLite has already rolled back a failed transaction, the SQLite ops store (`createSqliteOpsStore`) used to throw the error of its own `ROLLBACK` ("cannot rollback - no transaction is active") instead of the error that failed the transaction. It now rethrows the original error, as the SQLite store pack (`createSqliteStores`) already did. A second `close()` made while the store is still waiting for its calls to finish now resolves only once the database is closed, instead of at once. Both stores now open, configure and close their database through one shared module. Their schemas, schema versions and other behaviour are unchanged, so 2.3 still opens every file they write.
