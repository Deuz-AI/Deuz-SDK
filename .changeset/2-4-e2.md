A versioned-memory `forget` now reaches every copy of the forgotten record that a V3 run store keeps, not only the compiled context packages. When `redactForgotten(event)` redacts a package, the store also rewrites the runs that point to it: each copy of that package's retrieval block (the `<deuz_context pass="P" step="S">` message) in the run's history, in every checkpoint and in the stored result's messages, a terminal run's `result.messages` included, becomes a stand-in that keeps the block's opening marker and holds no record. The message count, roles and order stay the same. The rewrite happens in place: the run's revision and its last-save time do not change, so it does not move the run's retention, and a repeated forget changes nothing. A run saved after the forget is stored the same way, so a leg that was running during the forget cannot write the block back with its terminal save. A resumed run still finds the marker, drops the block and compiles that step again with refresh `'redacted'`, as before. The Postgres store reads the package state inside its SERIALIZABLE transaction, so a save that races the forget is retried. This applies to `createInMemoryAgentRunStoreV3`, `createSqliteAgentRunStoreV3` and `createPostgresAgentRunStoreV3`.

Known limits of the redaction: a leg that is running when the forget lands keeps the block in memory and can still send it until the leg ends or the run is resumed. Text the model wrote from a block (its answers, `result.text`, a compaction summary) and the results of the versioned memory tools (`memory_recall` output in tool messages, the transcript and a chat store) are not retrieval blocks and are left as they are. `forget` never touches chats, the transcript index or host files.

Retention stays explicit for every 2.4 store: no store deletes anything in the background, and every cutoff is exclusive, so a record stamped exactly at the cutoff stays. `ProcessOperationStore.prune` now refuses a malformed `terminalBefore` with a `TypeError`, and `ConditionalChatStore.pruneTombstones` refuses a malformed `before` with `InvalidRequestError`, both before deleting anything. Before, a missing or `NaN` cutoff pruned nothing or failed inside the database driver. The in-memory, SQLite and Postgres versioned memory stores now log the same `pruneOperations` warning, with `{ count, olderThan }`.

`DEFAULT_DURABLE_STREAM_RETAIN_MS` from `@deuz-sdk/core/ui` (24 hours) is the default retention for terminal durable streams. Prune with `store.prune({ terminalBefore: Date.now() - DEFAULT_DURABLE_STREAM_RETAIN_MS })`, for example from a durable schedule; the cutoff is compared on the store's clock.
