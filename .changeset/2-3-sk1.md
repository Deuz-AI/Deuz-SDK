The `deuz-sdk` Agent Skill's maintenance tooling is now in the repository, under `packages/core/tooling/skills/`. Its index and its docs page named generator and verifier scripts in a git-ignored directory, so nobody could regenerate or check the skill. No runtime code changed, and nothing in the published package changed.

- `generate-api-index.mjs` rebuilds `references/api-index.md` in both skill copies from `package.json` `exports`, tsup's entry map and a walk of the source that follows `export *`. The index lists every subpath with its values, its type-only names and a reverse lookup. The stamp date comes from `--date` or `SOURCE_DATE_EPOCH`, never from the clock, and names are sorted in a pinned locale, so the same sources give the same file on any machine. Run against the v2.2.0 sources, it reproduces the shipped 2.2 index byte for byte, apart from its "regenerate" line and one pair of names. The 2.2 file was sorted in a Turkish locale, where `I` sorts before `i`; `--locale tr` restores that order.
- `verify-skill.mjs` resolves every `@deuz-sdk` import, every quoted or backticked `@deuz-sdk/…` specifier (one of a package that does not exist, such as `@deuz-sdk/cli`, fails too) and every "`name` from `@deuz-sdk/…`" claim in `SKILL.md` and `references/*.md` against the real export table. It skips fences tagged `no-verify`. It fails when any stamp's package version or API-contract hash is not the current one, when the index differs from the generator's output, and when the two skill copies differ (`TESTING.md` aside). Given a directory, it grades agent answers by name alone.
- `sync-skill-copy.mjs` makes `skills/deuz-sdk/` the single source and mirrors it into `.claude/skills/deuz-sdk/` with `--write`. `extract-examples.mjs` writes each `ts`/`tsx` example as its own module, for the compile check `TESTING.md` describes.

Documentation fixes: the 2.0 notes said the Redis store pack had a run store, which it gained only in 2.3, and both changelogs now carry a correction. The docs deployment guide now gives the commands that drive `deploy/redeploy.sh`, in place of a script the repository never had, and deploys from `main`.
