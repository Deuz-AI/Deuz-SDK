'@deuz-sdk/core': minor

A native memory extraction that wrote only part of its memories is no longer reported completed. `reconcileAgentRun` used to settle an interrupted extraction as `'completed'` as soon as one record of its operation was in the memory store, so the facts the pass never wrote were lost without notice. A native run now saves how many store mutations its extraction planned on the extraction record (the new optional `AgentRunMemoryExtraction.planned`) before it writes any memory, and writes nothing when that save fails (the extraction is then `'failed'` and a later `reconcileAgentRun` runs it again). Deletions, which leave no record to find, are applied first and counted in `mutations`. `reconcileAgentRun` records the extraction `'completed'` only when every planned mutation is confirmed. When only some are, the extraction is recorded `'failed'`, keeps the confirmed count in `mutations` and an error with code `'memory-extraction-partial'`, is never run again, and the call reports a `memory-extraction-partial` warning on the new optional `AgentRunReconciliation.warnings` (and to `deps.logger.warn`). The extraction status union is unchanged. An extraction record a 2.3 process left without a planned count is settled as before. **Behaviour changes:** a record that a native extraction updates now carries that extraction's `metadata.deuz` run and operation ids instead of the ids of the operation that wrote it before; a native run saves its record once more per extraction (twice more when it both deletes and writes records); and a completed reconciliation no longer keeps the error of an earlier failed attempt.

`applyMutations(store, mutations)` is exported from `@deuz-sdk/core/memory`. It applies a plan from `remember(..., { apply: false })` or `planMemory` exactly as `remember` applies it: every upsert in one `upsert` call, then every delete in one `delete` call, then each invalidation.

`uiFromMessages(messages, generateId, { messageIds })` keeps the ids a stored chat gave its messages. Pass `ChatRecord.messageIds` (ids aligned with the canonical messages, as a native run's chat projection writes them) and each UI message keeps the id stored for its canonical message. `generateId` covers a message without an id (a missing or empty entry) and an id an earlier message already kept. The two-argument call is unchanged.

**`CallWarning['type']` is widened** with five members that 2.4 reports: `'embedding-mismatch'`, `'unaccounted-usage'`, `'context-source-failed'`, `'stream-store-error'` and `'memory-extraction-partial'`. Code that switches over the union should keep a default branch, as the `'other'` member already asks.
