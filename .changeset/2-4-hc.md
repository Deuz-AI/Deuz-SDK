**Nested V3 runs and context sources.** A nested V3 run claims the scope each built-in context source actually reads. A store-backed `createMemoryContextSource` or a `createTranscriptContextSource` pinned to a wide scope (for example one source per user) and narrowed by the compiler's `scope` is claimed at that narrowed scope, so a child whose compiler scope lies within its parent run's memory scope is no longer refused. A `ContextCompiler` instance passed as `context` now has its `scope` claimed too, as the compiler options' `scope` already was. A memory session source still claims its session's scope.

**Refused durable responses.** A durable `toDeuzAgentStreamResponse` refused at open because another producer holds the stream returns its subscription to the run's events at once. Before, the run, which the subscription had started, kept queueing every event (text deltas and raw tool results included) for a response that would never read them. A refused durable `createDeuzStream` drops what was queued and every later `writeData`, as it does after the stream ended.
