Native runs get opt-in ways to go on after a persistence or transport failure. No default changes.

- **A catalog change the run missed.** A native run with `onCatalogChange: 'accept'` could die between an MCP hot refresh and the save that records the refreshed catalog; while the server kept its new catalog, every resume failed with `MCP tool catalog changed across resume`. A resume with `onCatalogChange: 'accept'` now treats the change like the hot refresh it missed: its first write records the servers' catalog as a new binding revision, before its first model call, and it reports the same `warning` part (`setting: 'mcp'`). It still fails, and leaves the run untouched, while a call the model made against the recorded catalog is in flight (an MCP receipt in stage `'executing'`, or a call of the last turn that waits for its verdict or never started) and when the resume dropped the `mcp` entries. Under `'stop'`, the native default, the resume fails exactly as before. A resume that writes nothing records nothing.
- **Recording an effect that landed.** After a `tool-reconciliation-required` stop, an effect that did land could not be recorded: the run stayed stopped, or `retryToolCallIds` ran it again. The new resume option `reconciledToolResults: [{ toolCallId, output, isError? }]` (the shape of `clientToolResults`) records the outcome you found in the system the effect touched. The receipt takes `output` as the call's raw result, marked with the new `AgentToolReceipt.reconciled`, and the step goes on from it exactly as from a result the tool recorded (through `outputSchema`, `validateResult` and `toModelOutput`); the call never runs again. With `isError` the call is answered with `output` as its error. Only the run's unknown effects are accepted, each once and never also in `retryToolCallIds`; anything else fails the resume with a `TypeError` before anything is written. A call that waited for an approval is gated again on resume, as for a retry: pass the stored verdict with it. A stop for reconciliation now lists every call the store still holds as unknown in `unknownEffects`, also one the stopped resume tried to retry or reconcile, since that stop records nothing.
