**A V3 run can now charge the RAG context source's query embedding to its own ledger.** Before this, the embedding that a `createRagContextSource` query made inside a V3 run was never charged to the run. The compiler now gives every source query `accounting` when a V3 run compiles the step. It carries the run's execution context and a request id unique to the query. `ContextSourceRequest` gains `accounting` and `onWarning`. The RAG source passes them to `retrieve` as a new fourth argument, `charge`. Spread it into the options of `retrieve` or `hybridRetrieve`, for example `retrieve: (query, topK, signal, charge) => hybridRetrieve(query, deps, { topK, ...charge })`. The embedding is then reserved on the run's ledger before the call. An accounted embedder (`defineAccountedEmbedder`) settles its reported usage. An embedder that reports no usage stays held as unaccounted, never free, with one `unaccounted-usage` warning per run. The supervisor reads these charges through its watermark like any other ledger entry. Outside a run, and with a `retrieve` that ignores `charge`, nothing changes: `retrieve` is still called with three arguments and nothing is charged.
