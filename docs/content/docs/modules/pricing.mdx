whole swarm one shared budget. Everything lives behind the optional
`@deuz-sdk/core/pricing` module. Deuz reports usage and estimates; your application
owns billing.

### Long context and other tariffs

For the listed OpenAI models, prompts **above 272,000 tokens** use 2× input and
cache rates and 1.5× output rates for the **whole request**. The bundled rows
apply that tier automatically. See the [Astra model reference](https://developers.openai.com/api/docs/models/gpt-6-astra)
and [Sol model reference](https://developers.openai.com/api/docs/models/gpt-5.6-sol).

Batch, fast mode, regional processing, gateway markups and negotiated contracts
can use different prices. Supply a [custom price provider](#custom-rates-and-margins)
for the tariff you actually use. A model's price-table entry does not grant API
access or select a processing tier.

## `priceUsage`

Pass a model ID and the `Usage` returned by an SDK call. The result is a USD
number, rounded to six decimal places, or `undefined` if no price can be resolved.

```ts title="estimate.ts"
import { generateText } from '@deuz-sdk/core';
import { createOpenAIResponses } from '@deuz-sdk/core/openai';
import { priceUsage } from '@deuz-sdk/core/pricing';

const openai = createOpenAIResponses({ apiKey: process.env.OPENAI_API_KEY! });
const modelId = 'gpt-5.6-sol';

const { text, usage } = await generateText({
  model: openai(modelId),
  prompt: 'Explain what makes an agent run durable.',
});

const usd = priceUsage(modelId, usage);
console.log(text);
console.log(usd === undefined ? 'Price unavailable' : `$${usd.toFixed(6)}`);
```

### Same usage, different models

This example uses illustrative, separate output and reasoning counters. It is
local arithmetic and makes no API calls.

```ts title="compare-costs.ts"
import type { Usage } from '@deuz-sdk/core';
import { priceUsage } from '@deuz-sdk/core/pricing';

const usage: Usage = {
  inputTokens: 10_000,
  outputTokens: 2_000,
  reasoningTokens: 1_000,
  cachedReadTokens: 20_000,
  cacheWriteTokens: 0,
  cacheWrite1hTokens: 0,
  totalTokens: 33_000,
};

priceUsage('gpt-5.6-sol', usage); // $0.108
priceUsage('gpt-6-astra', usage); // $0.270
priceUsage('claude-fable-5-1', usage); // $0.255
priceUsage('claude-opus-5', usage); // $0.135
```

For Sol, that is **$0.040 input + $0.060 output/reasoning + $0.008 cache reads**.
This holds token counts constant; actual tokenization and reasoning usage vary
by model.

## Usage anatomy

`Usage` preserves the token counters available from a provider. `priceUsage`
applies the following calculation to those counters:

| Usage field          | How it is priced                                       |
| -------------------- | ------------------------------------------------------ |
| `inputTokens`        | Fresh input × `input`.                                 |
| `outputTokens`       | Reported output × `output`.                            |
| `reasoningTokens`    | Hidden reasoning × `output`.                           |
| `cachedReadTokens`   | Cache hits × `cachedRead`; default is 0.1× input.      |
| `cacheWriteTokens`   | Cache writes × `cacheWrite`; default is 1.25× input.   |
| `cacheWrite1hTokens` | One-hour writes × `cacheWrite1h`; default is 2× input. |
| `audioTokens`        | If present, × `audio`; default is the input rate.      |
| `serverToolUses`     | Excluded. Add per-call search/tool fees separately.    |
| `totalTokens`        | A usage total, not an additional charge.               |

<Callout title="Reasoning counters can overlap">
  The current OpenAI and Anthropic adapters can retain reasoning inside `outputTokens` while also
  reporting it in `reasoningTokens`. Because `priceUsage` adds both, those responses can be
  overestimated. For billing, normalize the provider's overlapping counters in your own
  `PriceProvider`. The arithmetic example above uses separate counters.
</Callout>

`generateText`, `generateObject`, `embed` and `embedMany` return usage directly.
For `streamChat`, consume the stream and then await `result.usage`. Embedding
calls populate input usage; their output and cache buckets are zero.

### Cache savings

`cacheSavings(model, usage, table?)` estimates what cache reads saved compared
with paying the full input rate for those tokens. It excludes cache-write costs.

```ts
import { cacheSavings } from '@deuz-sdk/core/pricing';

// Reusing the usage above:
cacheSavings('claude-fable-5-1', usage); // $0.195
cacheSavings('gpt-5.6-sol', usage); // $0.072
```

## `PriceProvider` and the `deps` seam

Use `createPriceProvider()` to connect the bundled table to calls through
`deps.priceProvider`. A [client](/docs/core/dependencies) can bind it once for
all calls. This enables live cost events and USD budget checks.

```ts title="client.ts"
import { createClient } from '@deuz-sdk/core';
import { createOpenAIResponses } from '@deuz-sdk/core/openai';
import { createPriceProvider } from '@deuz-sdk/core/pricing';

const deuz = createClient({
  apiKeys: { openai: process.env.OPENAI_API_KEY! },
  deps: { priceProvider: createPriceProvider() },
});

const openai = createOpenAIResponses();
const result = await deuz.generateText({
  model: openai('gpt-6-astra'),
  prompt: 'Review this architecture: one scheduler, many bounded agent tasks.',
});

console.log(result.text);
```

A custom `PriceProvider` can load prices from your own service. Its
`priceUsage(model, usage)` method may return a number, `undefined`, or a promise
of either. The optional `cacheSavings` method has the same return shape. Keep
these methods free of billing side effects: the SDK may request multiple
estimates for the same work.

## Metering: the `onUsage` callback

`onUsage` receives usage with the **model ID that actually ran**. In a tool loop,
it can fire multiple times as model invocations finish. Price those invocations
individually when a run switches models or delegates to another agent.

```ts title="meter.ts"
import { streamChat } from '@deuz-sdk/core';
import { createAnthropic } from '@deuz-sdk/core/anthropic';
import { createPriceProvider, priceUsage } from '@deuz-sdk/core/pricing';

const anthropic = createAnthropic({ apiKey: process.env.ANTHROPIC_API_KEY! });
const result = streamChat({
  model: anthropic('claude-fable-5-1'),
  prompt: 'Explain prompt caching with a short example.',
  deps: { priceProvider: createPriceProvider() },
  onUsage: (usage, meta) => {
    console.log({
      model: meta.model,
      reason: meta.reason,
      tokens: usage.totalTokens,
      estimatedUsd: priceUsage(meta.model, usage),
      agentPath: meta.agentPath,
    });
  },
});

for await (const text of result.textStream) process.stdout.write(text);
```

The call-level callback overrides `deps.onUsage`; they are not both invoked.
`UsageMeta` exposes `model`, `reason`, optional `ttftMs` and optional `agentPath`.
It contains no dollar amount. Aborted calls can report partial usage; a failure
before usage is available does not guarantee a callback.

<Callout title="Keep metering callbacks synchronous">
  `onUsage` is a notification hook; the SDK does not await an async callback. For database writes,
  collect records or enqueue work and explicitly await your application's flush before a request or
  worker exits.
</Callout>

## Live cost stream

With a price provider, `streamChat` emits `cost` parts through `fullStream` and
the [UI wire v2](/docs/modules/ui-streaming). Agent loops emit them at model-step
boundaries; a single-turn stream emits one before finishing. Tool or child-agent
work after an event can appear in a subsequent cost update.

```ts title="live-cost.ts"
import { streamChat } from '@deuz-sdk/core';
import { createOpenAIResponses } from '@deuz-sdk/core/openai';
import { createPriceProvider } from '@deuz-sdk/core/pricing';

const openai = createOpenAIResponses({ apiKey: process.env.OPENAI_API_KEY! });
const result = streamChat({
  model: openai('gpt-5.6-sol'),
  prompt: 'Outline a migration plan in five steps.',
  deps: { priceProvider: createPriceProvider() },
});

for await (const part of result.fullStream) {
  if (part.type === 'cost') {
    console.log({
      totalUsd: part.costUsd,
      stepUsd: part.deltaUsd,
      savedUsd: part.cacheSavingsUsd,
    });
  }
}
```

| Field             | Meaning                                                                  |
| ----------------- | ------------------------------------------------------------------------ |
| `costUsd`         | Cumulative estimated cost. Display it directly; do not sum these events. |
| `deltaUsd`        | Optional increment since the previous reported cost.                     |
| `cacheSavingsUsd` | Optional savings on cache reads, when available and positive.            |
| `stepIndex`       | Optional step index.                                                     |

In 2.1, tool-loop accounting prices individual invocations against their actual
model and preserves settled dollar totals across [durable resumes](/docs/agents/durable-runtime).
Changing models does not reprice previous calls at the final model's rate.
If an invocation cannot be priced, the loop cannot report a complete cumulative
cost. Missing pricing is **unknown**, not zero.

## The budget guardrail

For existing generation/tool loops, `budget` checks cumulative usage and estimated
cost at step boundaries. `budget.usd` needs a price provider; `budget.tokens` uses
reported token usage.

```ts
const result = streamChat({
  model: openai('gpt-5.6-sol'),
  prompt: 'Investigate the issue and propose a fix.',
  tools,
  maxSteps: 12,
  budget: { usd: 0.5, tokens: 100_000 },
  deps: { priceProvider: createPriceProvider() },
});

await result.consume?.();
```

The current step finishes before the check stops further work. Streaming emits
`budget-exceeded` before `finish`, and `providerMetadata.deuz.stoppedBy` identifies
`budget.usd` or `budget.tokens`. Resume retains prior usage and known cost.

Without a price provider, or with incomplete pricing, the USD condition cannot
protect the run. Include a token limit and a step limit as independent controls.
For admission checks before a model attempt, use native execution budgets.

## Native agent and swarm budgets

Native agents in 2.1 reserve estimated tokens and dollars **before dispatch**.
Parent and child contexts share a ledger, so delegated work consumes the same
budget. A USD limit requires a known USD estimate for admission.

```ts title="shared-budget.ts"
import { createExecutionContext, runAgent } from '@deuz-sdk/core/agent';
import { createOpenAIResponses } from '@deuz-sdk/core/openai';
import { createPriceProvider } from '@deuz-sdk/core/pricing';

const openai = createOpenAIResponses({ apiKey: process.env.OPENAI_API_KEY! });
const execution = createExecutionContext({
  budget: { usd: 2, tokens: 100_000 },
});

const result = await runAgent({
  model: openai('gpt-6-astra'),
  prompt: 'Propose a test plan for a durable task scheduler.',
  maxSteps: 4,
  maxOutputTokens: 2_000,
  execution,
  deps: { priceProvider: createPriceProvider() },
});

console.log(result.status, result.accounting);
```

| Accounting field               | Meaning                                                 |
| ------------------------------ | ------------------------------------------------------- |
| `spent`                        | Known actual token and USD amounts.                     |
| `reserved`                     | Still-held estimates, including uncertain attempts.     |
| `committed`                    | Spent + reserved.                                       |
| `unknownTokens` / `unknownUsd` | Counts of attempts whose actual amounts remain unknown. |

Missing usage or failed pricing keeps reservations held. Native sessions and
swarms persist the ledger for recovery; resuming cannot reset spend or loosen
saved parent limits. Verification callbacks that make SDK calls must forward
their `execution` and `signal`.

Admission uses estimates, so actual usage can exceed a reservation. The ledger
records that overage and prevents later admission when the limit is exhausted.
See [native agent budgets](/docs/modules/native-agents#mandatory-policy-and-shared-budgets)
and [swarm budgets](/docs/modules/swarm#policy-budgets-and-versioning) for persistence
and child-policy details.

## Custom rates and margins

Override individual rows for a deployment, or add your own model. **Each supplied
row replaces the complete row for that ID.** Spread an existing row to preserve
its cache rates and long-context tiers.

```ts title="custom-prices.ts"
import { createPriceProvider, PRICES_2026 } from '@deuz-sdk/core/pricing';
import type { PriceTable } from '@deuz-sdk/core/pricing';

const table: PriceTable = {
  'claude-opus-5': {
    ...PRICES_2026['claude-opus-5'],
    input: 4.5, // Example contract rates, not public list prices.
    output: 22.5,
    cachedRead: 0.45,
    cacheWrite: 5.625,
    cacheWrite1h: 9,
  },
};

const priceProvider = createPriceProvider({ table, margin: 1.2 });
// The factory retains other bundled rows and applies a 20% markup.
const usd = await priceProvider.priceUsage('claude-opus-5', usage);
```

`margin` is a multiplier, defaults to `1`, and also scales `cacheSavings`.
`createPriceProvider` performs no network calls and works in edge runtimes.

Passing `priceUsage(model, usage, table)` directly is different: the third argument
is the **entire lookup table**, with no automatic merge. To extend the bundled
table in that form, pass `{ ...PRICES_2026, ...table }`.

## Model lookup

Lookup first checks the exact ID, then tries a normalized ID with a supported
vendor prefix or trailing date/suffix removed. Its final fallback is the longest
known prefix of the original ID.

```ts
priceUsage('openai/gpt-6-astra', usage); // Resolves the Astra row.
priceUsage('my-private-model', usage); // undefined without a matching row.
```

Prefer exact IDs and explicit rows for new models. A family-prefix match can
resolve a price even when the variant has a different tariff. For strict
application billing, require `Object.hasOwn(table, modelId)` before estimating.
Do not turn `undefined` into a zero-dollar charge.

## `PRICES_2026` and `ModelPrice`

`PRICES_2026` is a bundled snapshot, not a live pricing feed. The highlighted rows
above were verified on the stated date; other bundled models retain their own
historical rates. Check the provider's tariff when updating a deployment.

`PriceTable` is `Record<string, ModelPrice>`. Each row requires `input` and
`output`, with optional `cachedRead`, `cacheWrite`, `cacheWrite1h` and `audio` rates.
Two optional context tiers are supported:

| Row field  | Trigger                                                        | Behavior                                      |
| ---------- | -------------------------------------------------------------- | --------------------------------------------- |
| `over200k` | `inputTokens + cachedReadTokens > 200_000`                     | Existing tier for selected Gemini rows.       |
| `over272k` | Fresh input + cache reads + both cache-write buckets > 272,000 | Tier used by the listed GPT-6 / GPT-5.6 rows. |

An active tier overrides rates for the whole call. Price individual invocations
before summing their costs; a run's accumulated tokens are not one long prompt.
`priceUsage` and `cacheSavings` select the same tier.

## API at a glance

| Export                                     | Use it for                            |
| ------------------------------------------ | ------------------------------------- |
| `priceUsage(model, usage, table?)`         | Estimate one invocation in USD.       |
| `cacheSavings(model, usage, table?)`       | Estimate savings from cache reads.    |
| `createPriceProvider({ table?, margin? })` | Inject pricing into calls or clients. |
| `PRICES_2026`                              | Read or extend the bundled rates.     |
| `ModelPrice`, `PriceTable`                 | Type your own pricing configuration.  |

Prices here cover the token buckets available in `Usage`. Per-request fees,
provider tools, storage, media jobs and application infrastructure need their own
accounting. Continue with [clients and dependencies](/docs/core/dependencies),
[UI streaming](/docs/modules/ui-streaming), [native agents](/docs/modules/native-agents)
or [swarms](/docs/modules/swarm).
