# 17 — Realtime voice, offline

**Shows:** the 2.3 realtime module, `@deuz-sdk/core/realtime`, on a scripted stand-in for the OpenAI Realtime WebSocket. `createRealtimeSession` dials the socket and configures the session (`session.update`); `connect()` resolves on `session-ready`. The user's question goes in as PCM16 audio (`appendAudio` in chunks, then `commitAudio` and `createResponse`, because the session uses `turnDetection: 'manual'`), and its transcript comes back. The model answers with a function call: the session runs the Deuz `get_weather` tool in this process, sends the result back and asks for the next response, and the model speaks its answer as audio chunks with a transcript. A typed follow-up (`sendText`) gets a second spoken answer. Every response reports its usage split by modality, priced through `realtimePriceTable`, and the session total is printed at the end. `[sent]` lines are the frames the session put on the wire; the other lines are the events your app receives.

**Run:** from the repo root, `npm install && npm run build`, then `npm run dev -w @deuz-examples/17-realtime-offline`. No API key and no network: the socket comes from `deps.webSocket`. Node ≥ 22.6 for the type stripping.

**Real provider:** delete `webSocket: scriptedServer` from `deps` and pass a key: `createOpenAIRealtime({ apiKey: process.env.OPENAI_API_KEY })('gpt-realtime')` (see the `REAL PROVIDER` comment in `index.ts`). Then give step 2 a real question: its 1.2 s of audio is silence, in which a real model hears no question, so append microphone audio (PCM16, 24 kHz, mono) or ask with `sendText`. The steps wait for each answer by the order of the events (`nextAnswer` in `index.ts`), not by a response id, because the provider names its responses. On a server, Node ≥ 22 sends the key as an `Authorization` handshake header. A browser cannot send that header and must never hold the key: mint a short-lived client secret on your server with `createOpenAIClientSecret` and pass it to the session as `ephemeralToken`. Gemini Live uses the same session API with `createGeminiLive({ apiKey })('gemini-live-2.5-flash-preview')`; its input audio defaults to 16 kHz (pass `inputSampleRate: 24_000` for audio like this example's) and its voices have other names (`Kore`, …). Neither wire is live-verified: the message shapes come from the providers' official SDK types, so make one real call before you ship.

**Look at:** a response's `usage` event arrives before its `response-done`, and the tool call runs only because its response completed: the calls of a cancelled or truncated response are reported as `tool-call-cancelled` and never run. The tool's result goes back as a `function_call_output` item followed by a new `response.create`, without any code of yours. The prices are illustrative, because no realtime prices ship with Deuz: text is priced under the model id and audio under `audio:<model>`, and if a modality a response used has no price, that response is unpriced, the session emits one `unpriced-model` warning and keeps going. OpenAI bills the input transcription separately (by the transcription model), so it is not in the session's usage.
